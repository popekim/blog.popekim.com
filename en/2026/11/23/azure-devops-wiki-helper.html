Where Was I in the Wiki? I Built Azure DevOps Wiki Helper

Pope Kim Nov 23, 2026
  • dev
  • azure devops
  • chrome extension
  • productivity

At our company, we use Azure DevOps Wiki. We also use it to document work processes from time to time: what to do first when tackling a task, what to check next, and so on.

Having these procedures written down makes it easier to explain things to people, but these days, it also helps quite a bit with AI automation. You can give the document to an AI and tell it to follow the procedure. Getting those steps out of people's heads and into writing pays off.

But there was a small inconvenience when a person actually followed the document to do the work.

"So, where was I?"

I know the order, but I don't know how far I've gotten

Process documents are usually written as numbered lists. Do step 1, then step 2, then step 3, then step 4.

If the procedure is short, that's fine. But when each step involves running something and waiting for the result, or switching to another screen to check something before coming back, you can sometimes lose your place. Even more so if another task interrupts you along the way.

The document is right in front of you, yet you have to read through it again to figure out which step you just finished. Numbers tell you the order of the work, but they don't mark how far you've gotten.

So I wanted checkboxes. If I could check one off after finishing each step, I could immediately see what to do next when I returned to the document.

In Markdown, you can write something like this:

- [ ] First step
- [ ] Second step
- [ ] Third step
- [ ] Fourth step

But in Azure DevOps Wiki, checkboxes created this way are disabled by default. You can see them on the screen, but you can't click to check them off.

Editing and saving the document just to check a box wasn't how I wanted to use it, either. This is a shared procedure that multiple people follow repeatedly. There's no need to save my progress on this particular run in the company's shared document.

I just wanted to check things off as I went.

So I made a small Chrome extension

I built Azure DevOps Wiki Helper to solve this inconvenience.

What it does is simple: it makes the checkboxes in Azure DevOps Wiki clickable. Now I can write a process document as a checklist and check off each step as I finish it.

The important part is that checking a box does not save the change to the actual wiki document. It's a personal checkbox for marking my progress as I work, without modifying the shared document's contents.

I can see how far I've gotten on my own screen without leaving my completion status in a procedure that other people also need to follow. That was exactly the functionality I wanted.

All I needed was a checkmark

Documenting a process is useful in many ways. You can use it to explain the work to someone new, or to assign a task to an AI. But when a person follows that document, a small feature like this can be something they miss.

This time, that feature was the ability to check off each step. It didn't call for building an elaborate tool; a simple Chrome extension was enough to solve it.

If, like me, you write down procedures in Azure DevOps Wiki and find yourself asking "Where was I?" while following them, give it a try.
